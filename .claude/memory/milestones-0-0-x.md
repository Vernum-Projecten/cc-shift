Milestones start at `v0.0.1` and step `v0.0.2`, `v0.0.3`, never a `v0.1.0`
opener.

**Why:** the owner runs an `0.0.x` line while a project is pre-release and
wants small, frequent cuts.

**How to apply:** a plan laid out deliberately places each issue in the
milestone its build order implies; work found while implementing goes in the
current milestone (`.claude/rules/issue-workflow.md`). Milestones have no due
dates until the owner sets them. See [[cut-releases-promptly]].
